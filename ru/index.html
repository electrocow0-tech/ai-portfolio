01

Производитель промышленного оборудования · Авито + Telegram

Двухканальный AI-продавец для B2B-производителя

Задача

Сотни SKU, спецификации и прайсы. Первый контакт — на Авито, разговор продолжается в Telegram. Инженеры отдела продаж тонули в рутине, клиент повторял контекст при смене канала, вечерние и выходные заявки ждали до утра.

Моя роль

Разобрал воронку с отделом продаж, согласовал сценарии возражений и правила передачи менеджеру, спроектировал архитектуру и реализовал систему целиком.

Что я построил
  • Единая память клиента между Авито и Telegram: короткая история, саммари, структурированные факты.
  • RAG по документации и прайсам из Google Drive с инкрементальной переиндексацией по хешу каждые 15 минут.
  • Агент на state machine: квалификация → подбор → возражения → передача менеджеру → дожим.
  • Перехват диалога менеджером с блокировкой автоответов и возвратом в AI-режим.
Инженерные решения
  • Фильтр по SKU в retrieval — поиск не уходит к похожей, но другой модели.
  • Нет подтверждения в базе — нет цифры в ответе: вопрос уходит менеджеру.
  • Идемпотентная запись в CRM, ретраи с backoff, видимая очередь ошибок.
Результат

Два канала продаж работают как одна воронка 24/7, менеджер получает лид с уже собранными требованиями.

Что это показывает → Перевод процесса продаж в управляемую систему: RAG с защитой от выдумок, память, human handoff, надёжные интеграции.

Python · FastAPI · PostgreSQL · Redis · RAG · LLM API · Pydantic · Google Drive API · Telegram · Avito API · CRM API · n8n · Docker · Grafana

02

Отделы продаж от 20 менеджеров · веб-кабинет

Голосовой AI-тренажёр продаж

Задача

Тренировки с бизнес-тренером требуют расписания, новички учатся на живых лидах и сливают их, текстовые сценарии в LMS голосового навыка не дают, а РОП физически не успевает заниматься с каждым.

Моя роль

Согласовал с руководителем чек-лист и веса критериев — тот же лист, что в контроле качества реальных звонков. Спроектировал и реализовал сервис целиком: голосовой агент, оценку, кабинет, админку и инфраструктуру.

Что я построил
  • Менеджер открывает кабинет и в реальном времени говорит голосом с виртуальным клиентом, который возражает, перебивает и не выдаёт потребности сам.
  • Сразу после звонка — разбор по чек-листу и голосовая обратная связь «от руководителя».
  • Оценка и запись разговора попадают в таблицу руководителя и в админку.
  • AI-коуч смотрит историю менеджера и собирает следующего клиента под его слабые места, без повторов сценариев.
Инженерные решения
  • Один чек-лист с контролем качества звонков: видно, переносится ли навык из симуляции в реальные разговоры.
  • Итоговый балл считает код по весам критериев, модель отвечает только на вопросы чек-листа.
  • Страница с голосовым виджетом отдаётся отдельным статическим контейнером, API — только /api через Traefik: заголовки ответа API-фреймворка обрывали голосовую сессию через секунду.
Результат

Тренировка на 10–20 минут в любое время без тренера и без риска для живых лидов; руководитель видит динамику каждого менеджера.

Что это показывает → Realtime-голосовой продукт от UX до инфраструктуры и связка «обучение ↔ контроль качества» на одной методике.

ElevenLabs Conversational AI · LLM API · Python · FastAPI · Traefik · Docker · Google Sheets API · web cabinet

03

Автодилер · CRM без доступного API

Автоматический контроль качества звонков

Задача

Сотрудник 3–4 часа в день выгружал данные и слушал записи, в выборку попадало 20–30% звонков. Доступа к API CRM не было.

Моя роль

Собрал с руководителем отдела продаж чек-лист из 15 критериев и правила для пограничных случаев — итеративно, по ревью-сессиям с заказчиком. Спроектировал и реализовал оба контура.

Что я построил
  • RPA-робот собирает реестр сделок и записей из CRM без API: нормализация, дедупликация, upsert.
  • Транскрибация с диаризацией и разметкой «менеджер / клиент».
  • Два LLM-вызова: классификатор типа звонка по содержанию и скорер по чек-листу.
Инженерные решения
  • Итоговый балл считает код, а не модель: ответы приводятся к сетке «0 или вес критерия».
  • Эталонные транскрипты с ожидаемыми оценками прогоняются при каждом изменении критериев.
Результат

Проверяются все звонки, а не выборка; данные в аналитике через 1–2 минуты после сделки, сотрудник контроля занимается спорными случаями.

Что это показывает → Работа там, где нет API; LLM-оценка, которой можно доверять; перенос экспертизы заказчика в правила системы.

Python · browser RPA · PostgreSQL · AssemblyAI · LLM API · S3 · Google Sheets API · Telegram Bot API · Docker · Grafana

04

Собственный продукт · медиа и SMM

AI-редакция Telegram-канала

Задача

Обработать большой поток источников, сохранить стиль канала, не публиковать непроверенное и оставить решение человеку.

Моя роль

Продукт целиком мой: от гипотезы и прототипа на n8n до отдельного Python-сервиса.

Что я построил
  • Сбор из Telegram, RSS и search API с дедупликацией на входе.
  • Четыре роли — фильтр, копирайтер, редактор, критик — с JSON-контрактом между шагами.
  • Quality gate: ниже 7/10 — переписывание с фидбеком критика, до 3 итераций; одобрение кнопками в Telegram.
Инженерные решения
  • Своя модель и температура на каждую роль — на порядок дешевле одной топ-модели на всех шагах.
  • Переключение LLM-провайдеров через base URL — устойчивость к блокировкам.
Результат

Ежедневный дайджест с обязательным ручным одобрением, около $100 в месяц на работу конвейера.

Что это показывает → Мультиагентный конвейер с контролем качества и практичной экономикой; путь от no-code прототипа к сервису.

Python · aiogram · APScheduler · Telethon · LLM API · n8n · PostgreSQL · Docker
